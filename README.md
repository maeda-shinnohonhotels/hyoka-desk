# 評価デスク

一般社員の人事評価（自己評価 → 一次評価 → 面談 → 最終決定 → 給与改定）をクラウドで管理する Web アプリ。

## 構成

- `public/` … 静的サイト（ビルド不要）。どこに置いても動く。
- データベース：Supabase プロジェクト `hyoka-desk`（東京リージョン、ref `ulvkofygpbvufpgkrmhm`）
- ログイン：メールアドレスにログインリンクを送る方式。社員名簿（`employees.email`）に登録されたアドレスだけが使える。

## 権限

| 誰 | 見られるもの | 入力できるもの |
|---|---|---|
| 本人 | 自分の自己評価、公開済みの最終結果 | 自己評価（受付期間中・提出前のみ） |
| 評価者（1次） | 担当する社員の自己評価・一次評価・最終評価 | 一次評価（提出前のみ） |
| 評価者（2次） | 担当する社員の自己評価・一次評価・最終評価 | 最終評価（面談後の最終決定、提出前のみ） |
| 人事・取締役 | すべて（給与を含む） | すべて |

給与（`salary_revisions`）は人事・取締役だけが見られる。一次評価は本人には見えない。
評価者は「社員・評価者」で担当の社員に割り当てる。1次・2次のどちらを入力するかは、割り当てた評価者の権限で決まる。
権限はデータベースの行レベルセキュリティ（RLS）で強制しているので、画面を改ざんされても越えられない。

## 1期の流れ（人事）

1. 「期間・設定」で新しい期間を作り、施設ごとの KPI 達成率を入力する
2. 「社員・評価者」でメールアドレスと評価者（1次・2次）を設定する
3. 期間の状態を「自己評価 受付中」にする → 本人が入力・提出
4. 「一次評価 期間」にする → 評価者（1次）が一次評価を入力し、面談後に評価者（2次）が最終評価を提出
5. 「評価一覧」で内容を確認して承認し、本人に公開する
6. 「給与改定」で「前期の改定後を取り込む」→「評価ランクの昇給額を反映」→ 固定残業手当などを確認・修正して CSV 出力
   - 推薦などで評価結果と違うランク・昇給額にするときは、評価欄に手打ちしてから「反映」する（空欄なら最終評価のランクを使う。ランクだけ入れると、そのランクの昇給額になる）
7. 期間を「締め」にする（すべて編集不可）

点数：10項目 × 1〜5点 ＋ 事業所の実績・成果（KPI 1〜5点 × 2）＝ 60点満点
ランク初期値：A 49点〜 +10,000円 ／ B 37〜48点 +5,000円 ／ C 25〜36点 +2,000円 ／ D 〜24点 昇給なし（期間ごとに変更可）

## 移行済みデータ

- 正社員の名簿（パートは除く）
- 2025.10～2026.9期：給与の改定前／改定後と、Excel の評価欄（点数やメモ）を `legacy_eval` に移行済み。状態は「締め」
- 2026.10～2027.9期：「準備中」で作成済み（評価項目10個を設定済み）
